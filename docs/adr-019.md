# ADR-019: Strategy Experiment Lab v0.1

Date: 2026-09-30. Research experiments only; production execution DISABLED.

Research -> Thesis -> Opportunity -> Strategy -> Backtest -> Validation -> Human Review
-> Future Paper Eligibility. No broker or forward-paper operation is added.

1. Implement exactly two baseline hypotheses: LONG_TERM_QUALITY_GROWTH and
   SWING_TREND_MOMENTUM, both v1.0.0, BACKTEST. Use the established lowercase domain
   enum internally; display LONG_TERM / SWING in reports. Three separately versioned
   swing sensitivity probes remain variants of the same hypothesis, not new strategies.
2. Extend the shared StrategyVersion with optional typed experiment parameters. Omit
   absent fields during serialization to preserve legacy version digests. One dispatch
   function selects implementations in research, backtesting and independent replay.
   Reuse existing proposal generation, FixedNotionalSizer, indicators and Risk Engine.
3. Quality-growth exposes independent, source/unit/basis-bound metric gates and
   qualitative business/growth evidence, thesis, valuation and portfolio checks.
   Mandatory thresholds remain UNSET. No universal stock score or price-only sale.
4. Trend-momentum uses configurable 200/50 SMA, strict 50<RSI(14)<75, prior-20-session
   volume and ATR(14). ATR 2x / 20 sessions / 30 calendar days are labeled unapproved
   experimental review defaults. Sizing/approval controls remain UNSET. Stops/exits
   emit EXIT_REVIEW; this phase does not grant automatic sell permission.
5. Freeze complete plans before evaluation: exact versions, periods, universes, capital,
   datasets, costs, gates and sensitivity probes. Definitions are registered before runs.
   Enforce the same rules/costs/universe across periods and one-factor development-only
   probes; no grid, automatic ranking, selection or OOS parameter tuning.
6. Reserve data exposure before evaluation. Serialize reservations through a database
   lock row; overlapping security dates involving OOS cannot be reused as unseen,
   including renamed datasets, new experiment IDs, or earlier development exposure.
   The two baseline hypotheses share one preregistered cohort; repeated retrieval
   returns the stored result, not new unseen evidence. Failures retain exposure.
7. Physically separate period datasets, retaining only causal warm-up. Reuse cutoff
   isolation and nested timestamp checks. Compare exact deterministic replay twice.
   Lab validation adds reproducibility, fresh preregistered OOS and required controls
   to existing StrategyValidationReport, with human review explicitly required.
8. Keep InvestmentPolicy unchanged: whole-share buys, USD 160 attributed sleeve and
   swing forward-evidence requirements still apply. Larger synthetic starting cash
   does not enlarge that sleeve. Requested fractional simulation is reported as
   BLOCKED_BY_POLICY; do not silently bypass risk to generate attractive results.
9. No reliable historical provider/thesis archive is installed. Use a fixed, explicitly
   synthetic three-period study for software verification, not financial validation.
   Preserve zero-trade and unsuccessful findings. Real regime coverage is unverified.
10. Add additive lab-plan/exposure tables beside ExperimentRegistry, no API or scheduler.
    All data text remains inert. Store active synthetic registry outside OneDrive;
    future private deployment requires migrations, authorization and operational review.

Exposure protection covers this retained registry only. It cannot detect research done
elsewhere, a deleted database, falsified provider identities, or human prior knowledge.
Existing 60-session non-synthetic forward validation remains unsatisfied; historical,
OOS and synthetic sessions contribute zero. Nothing grants live eligibility.
