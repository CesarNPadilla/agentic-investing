# ADR-015: Startup policy and incremental portfolio evidence

Status: Accepted, 2026-09-29.

## Context

Policy v0.2 domain models already exist. Deployment can only use defaults without Python
injection, analysis requests unintentionally clear omitted evidence, and retained thesis
revisions cannot be retrieved through the authenticated API.

## Decision

- Load an optional UTF-8 JSON file through `AIL_INVESTMENT_POLICY_FILE` at startup.
  No configured file means current safe defaults. An unreadable/invalid configured file
  aborts startup with a sanitized error. Reject simultaneous file and Python injection.
  Existing literal safety constraints and UNSET controls remain unchanged; no hot reload.
- On analysis enrichment, inherit omitted fields from the parent observation. Explicit
  null clears nullable evidence; an empty list clears collection evidence. Validate the
  resolved input, recalculate analytics and persist a new derived observation. Never mutate
  the parent, automatically carry evidence to a new snapshot, or invent missing data.
- Expose authenticated thesis revision history with ascending revision order,
  `after_revision` cursor and maximum page size 500. Read persisted revisions only.

## Consequences

No broker adapter changes, order routes, strategy signals or schema/table migration are
needed. Configuration and audit retrieval become usable without source edits. Policy file
changes require restart; callers must explicitly clear evidence they intend to remove.
Stored history remains private application data, not tamper-proof against administrators.
