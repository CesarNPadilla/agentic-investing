# Guardian review host lifecycle

The staged host accepts one provisioned review context and exactly two ordered requests: PREPARE_REVIEW_REFERENCE, then CONFIRM_REVIEW_CONSUMPTION. Each request uses a fresh single-use guardian exchange pipe. The owner app retains its independently verified signed receipt between those requests. Replies carry no recovery, reset or execution authority.

Startup inspects existing reference/journal evidence and rejects retained state requiring reconciliation. Before opening a pipe it exclusively creates a host-start marker. That retained marker prevents concurrent host admission and reuse of this directory after interruption. Publication, transport, ordering and stop failures close the active pipe and retain a blocked terminal marker; no path clears state or retries automatically. Successful completion verifies matching retained review evidence and records a closed terminal state.

The provisioned envelope digest is supplied by trusted deployment code, never a request. Digest equality alone does not prove fresh provisioning or independently anchored history. Actual protected provisioning and directory permissions remain necessary qualification gates. If all guardian markers are maliciously deleted, this model alone cannot detect a full rollback; it is not immutable storage against a compromised guardian.
