# Webull quote evidence and bounded retail event probe

The new diagnostic depth parser accepts only SCHB, requires positive finite prices/sizes, chooses best bid/ask across levels, rejects crossed prices, and rejects future or older-than-30-second timestamps under the explicit Unix-millisecond interpretation. It preserves the response-byte digest and UTC receipt. Timestamp schema, clock, halt status and full runtime integration remain blockers even for a fresh quote. It provides no execution path or configurable override.

Twelve new tests cover fresh evidence, sorting, foreign symbols, malformed timestamps, stale/future timestamps, invalid depth and crossed markets. All 330 selected paper/control/Webull quote tests pass; Ruff checks pass.

A real quote attempt was rejected by the adapter; its raw failed response was not retained and its exact rejection cause is not established. A subsequent independent observation parsed successfully at an apparent age of 4.166 seconds. [The recorded observation](examples/webull-sandbox/quote-adapter-observation.json) retains all unresolved source blockers. No accepted quote clears a failed risk observation or authorizes trading. No working event journal or ledger was mutated by these standalone probes.

The selected private cash account was used for a TLS retail gRPC subscription to `events-api.sandbox.webull.com`. A disposable diagnostic process was externally bounded to twelve seconds and auto-retry disabled. Subscription acknowledgement succeeded; zero heartbeats and order events were observed. [Probe evidence](examples/webull-sandbox/bounded-event-probe.json) does not claim stream health, missed-event replay, order acceptance or persistent-service supervision. SDK logs/payloads were suppressed; no order was placed to manufacture an event. The [retail event documentation](https://developer.webull.com/apis/docs/reference/custom/subscribe-trade-events/) describes acknowledgement, heartbeat/error and order messages but does not establish replay coverage in the reviewed interface.

The next protected-reset architecture choice is a dedicated non-administrator Windows identity for the paper runtime, with owner authentication retained under the owner's existing login and a protected controller enforcing action scope and counters. A separate Windows VM is an alternative. Neither topology has been provisioned or permission-qualified. Merely naming an account is not OS isolation, and no account/password or privilege changes have been performed.

Next independent work includes strict selected-account read adapters, Webull cash ledger/accounting and longer bounded event health checks. Deployment/reset qualification requires the owner to choose the OS boundary before account provisioning. Existing numerical policies, trial activation, live permission, Alpaca state and sealed historical/OOS evidence remain unchanged.
