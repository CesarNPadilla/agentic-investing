# Webull untrusted controller request boundary

The runtime outbox is a request channel, not an approval source. `security/webull_control_request.py` defines the initial strict request format for `REQUEST_READONLY_SNAPSHOT` and `REQUEST_RESET_REVIEW`. Direct latch clearing, broker orders, claimed owner identity, approval fields, execution flags and extra fields are rejected. The parser accepts at most 4 KiB of UTF-8 JSON, rejects duplicate keys/nonfinite constants, requires the controller-selected account binding and a canonical UUID4 request identifier, and checks the format of the expected state digest.

Parsing never grants admission. The diagnostic receipt explicitly leaves caller authentication, owner approval, state-digest verification, replay checks, reset and execution false. Repeated parsing of a request is not replay protection. The request's expected state digest is an untrusted concurrency precondition to compare with protected state later, not evidence that reconciliation passed. No claimed username, SID, localhost origin or runtime-written receipt can establish owner authority.

This phase implements the request contract only. No service, named pipe, broker route, passkey integration or protected state writer is deployed. Existing Alpaca owner receipts and scoped read-only recovery acknowledgements are not adopted as Webull reset approvals. No credentials or authority records have been copied into runtime-readable locations.

The remaining controller must obtain caller identity from the OS-authenticated channel, verify action-bound owner authentication independently of runtime input, compare protected account/state/policy versions, and atomically enforce durable request/approval replay prevention. Reset admission must enforce the approved order: next NYSE trading day, fresh qualified reconciliation, then explicit owner approval. Independent stops remain latched. Missing provider accounting/status evidence continues to block admission even when owner authentication succeeds.

Seventeen tests cover malformed/ambiguous input, foreign account binding, forged approval/identity fields, forbidden actions and the absence of admission/replay authority. See [qualification evidence](examples/webull-sandbox/control-request-contract-qualification.json). This contract does not qualify the controller, reset or trial launch.

Staged reset-review follow-up: [the synthetic prerequisite checker](webull-reset-review-prerequisites.md) now binds request/account/state/policy/calendar/credential and enforces next-NYSE-day, fresh reconciliation, ordered five-minute owner approval and independent-stop/source blocks. It provides no real passkey proof, durable approval consumption, controller admission or latch mutation; no executable risk policy or activation changes.
