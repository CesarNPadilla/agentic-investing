# Webull runtime private-file boundary

The completed directory-authority fixture establishes scoped denial of deployment-directory DACL and owner rights. It does not establish access isolation for existing files under the owner's private profile.

The new fixture requests READ_DATA, WRITE_DATA, DELETE, WRITE_DAC and WRITE_OWNER handles to four fixed existing files: Webull production credentials, Webull sandbox credentials, the public owner passkey enrollment record and the private cash-account selection record. All 20 requests must return access denied (5). The native helper uses OPEN_EXISTING and closes granted handles immediately; it never reads file contents, writes data, changes ownership/DACLs, deletes a target or calls a broker. DELETE access is only a requested right, never a delete operation. No credentials are copied. The public passkey record contains no private authenticator key; its integrity still belongs outside runtime write authority.

The elevated owner wrapper verifies that target files exist, are not reparse points and are not runtime-owned; it preserves owner/DACL, file length and last-write metadata for comparison after the check. It requires a protected diagnostic Code/Logs/Receipts layout, exact retained client hash, runtime identity/non-admin report, positive dummy read/write handle controls, exactly one result for every file/right pair, empty stderr and a zero persisted process exit. A passing report is exclusively written in Receipts after the runtime account is disabled. Failure preserves diagnostics and writes no acceptance receipt. A dummy file in Logs and client artifacts are retained. Parent/host death can interrupt cleanup; this is not a supervised service.

Seven real native regressions parse/compile the wrapper and embedded client, exercise all five handle grants and missing-path errors on dummy files, confirm the dummy contents are unchanged, and demonstrate read-data denial with a temporary dummy-file DACL. Actual credentials are never used by those tests.

Read-only owner-context metadata inspection of the two Webull credential files and public passkey record found no runtime, Everyone, Authenticated Users or Users ACE. Their ACLs are inherited; this limited check does not establish all effective groups, privileges, ancestor traversal or runtime-token denial. The selected-account record is included in the prepared native fixture, not promoted by that three-file metadata audit.
