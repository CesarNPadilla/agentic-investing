# ADR-017: Opportunity & Strategy Engine v0.1

Date: 2026-09-30. Implemented for research and human review only.

Reuse ResearchAssessment, revisioned PositionThesis, policy scopes, experimental
attribution, reconciliation and deterministic risk. Add provider-neutral internal services:

```text
Data / fundamentals / news -> ResearchAssessment -> reviewed Thesis
    -> InvestmentOpportunity
        -> LongTermStrategy (5-10+ years)
        -> SwingStrategy (experimental, configured sessions/days)
    -> TradeProposal -> independent Risk -> Human Review / Reject -> STOP
```

Execution and paper-broker translation are outside this boundary. No live strategy status,
execution method, order route, scheduler or broker connection is added.

Decisions:

- Preserve thesis, valuation, catalysts, risk, fit, concentration and quality separately.
  No universal score, automatic Mag7 completion, selling or rebalancing.
- Share evidence checks and bounded sizing plumbing; keep strategy rules, horizons and
  parameters in separate concrete long-term and swing classes.
- Reviewed categorical valuation/fit decisions start UNSET. No universal valuation
  thresholds are invented. Configure decisions for the specific reviewed research context;
  changes require a new strategy version. Local authorization references record owner
  review, not authentication or execution approval.
- Extend existing TradeProposal, retaining its nested HypotheticalTrade and original names.
  Add opportunity/assessment/version/configuration links, concentration, capital, data time
  and lifecycle metadata. See the runbook mapping; no redundant trade fields are introduced.
- Independent review replays strategy content and applies existing deterministic policy
  checks. Confidence cannot change sizing or risk. Generic proposal review alone cannot
  qualify an opportunity-backed proposal.
- Persist immutable versions and atomic evaluation bundles in additive SQL tables. Version
  registration is separate: failure may leave a registered definition, never a persisted
  opportunity without its proposal/review/audit bundle.
- Inject time, adjusted OHLCV, historical availability and exact exchange session closes.
  Providers must attest calendar and point-in-time adjustment provenance.
- Exit rules produce EXIT_REVIEW only. Future backtests must separately define fills,
  costs and intrabar ambiguity. They reuse the same strategy methods.

Tests use synthetic inputs and temporary SQLite. PostgreSQL operations, trusted providers,
historical/forward-paper qualification and owner configuration remain gates. Policy defaults
and the USD 160 experimental ceiling are unchanged.
