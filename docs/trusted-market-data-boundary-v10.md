# Trusted market-data and session boundary — proposal

**PROPOSED_REQUIRES_APPROVAL; not connected to execution.** A future broker-neutral trusted quote adapter must return symbol, venue, currency, source/provider identity, bid, ask, last, provider event timestamp, receipt timestamp, status, and explicit raw/adjusted basis. An independent exchange-calendar/session adapter must return regular-session state in America/New_York, including weekends, holidays, early closes, halt/auction uncertainty, and calendar version. Clock synchronization and provider outage monitoring are required. Broker-specific order/session capabilities remain behind each Broker Adapter.

Proposed 30-second maximum quote age and 60-second coherent portfolio-snapshot age apply at risk review and immediately before any future submission. Reject future-dated, missing, inconsistent, crossed, nonpositive, unsupported-currency, or stale executable quotes; define an approved side-specific conservative price and fee buffer before implementation. Missing bid/ask cannot silently fall back to historical adjusted close, news, web content, agent text, or LLM output. A corporate action requires instrument/price-unit reconciliation before an order. If quote providers disagree or fail, block new entries and escalate; do not guess. Historical research data and its adjustment vintages remain a separate nonexecuting evidence class.

`AGENT_OPERATION_24_7` means research and monitoring may run continuously. Proposed `BROKER_ORDER_EXECUTION` permits only authenticated, human-approved, whole-share BUY LIMIT/DAY orders during a verified regular core session for an approved symbol and broker capability. Pre-market, after-hours, weekends, holidays, and after early close are blocked. An order tagged `core` is insufficient proof the exchange is open. Extended-hours trading is not proposed. No assumption is made that Robinhood and Webull have identical session semantics. A missing trusted calendar or clock fails closed.
