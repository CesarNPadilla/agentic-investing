# Runtime directory authority verification

The completed file-access and native-pipe fixtures do not establish whether the actual runtime token can change deployment directory permissions or ownership. This new owner-run fixture tests that specific gap without setting any directory DACL or owner.

The client requests existing directory handles with WRITE_DAC, WRITE_OWNER and both rights together, across Root, Code, Config, Receipts, RiskState, BrokerSecrets, OwnerControl, Logs and Outbox. All 27 requests must return Win32 access denied (5). Missing paths and other errors fail the test; they cannot count as denial. A new runtime-owned dummy directory in Logs supplies a WRITE_DAC positive control, so an unavailable or universally failing native helper cannot produce a pass. No privileges are enabled. This tests the current token's handle acquisition, not every privilege activation or elevation avenue.

The elevated owner wrapper refuses an enabled runtime or a reparse directory, verifies protected administrator-owned directory ACLs, retains their owner/DACL values and the client code digest, runs a hidden client with a 30-second wait, captures its exit code and disables the account in cleanup. It requires exact area/right inventory, empty stderr and unchanged owner/DACL values, then exclusively writes the acceptance report to Receipts. Failed attempts retain diagnostics and never write a passing receipt. The dummy positive-control directory and client artifacts are retained. Parent or host termination can interrupt cleanup; no supervised service or crash-cleanup qualification is claimed.

Five native regression tests parse/compile the actual embedded helper, verify all three grants on a disposable owner-controlled directory, distinguish missing paths from denied access, and demonstrate an explicit ownership-right denial on another disposable directory. Only the regression directory receives a temporary test DACL, restored before its removal; deployment ACLs remain untouched. Read-only structural inspection of the nine deployment directories passed. The actual runtime-account fixture passed and has been independently inspected.
