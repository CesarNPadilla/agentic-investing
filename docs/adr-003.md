# ADR-003: Broker-independent adapters and normalized domain models

Status: accepted; synthetic read-only foundation implemented.

## Context

Research and portfolio logic must not depend on a broker SDK or its response
format. Market quotes and account holdings have separate responsibilities.

## Decision

- `MarketDataProvider` returns normalized `Quote` objects.
- `BrokerReader` returns normalized `Account`, `Position`, and `CashBalance` objects.
- Adapter implementations own vendor-specific translation and transport handling.
- Monetary amounts and quantities use finite decimals; positions support fractional
  and negative quantities. Domain objects are frozen and reject extra fields.
- Unknown accounts raise `AccountNotFound`; transport failures use
  `BrokerUnavailable`. Failure must not be represented as an empty portfolio.
- Broker reads have no order submission or cancellation methods.

`SampleBrokerReader` supplies explicitly fictional account data for contract
tests. It performs no network requests and is not connected to the API or research
orchestrator. Its values are fixtures, not current balances or valuations.

## Validation

Contract tests exercise normalized reads, account isolation, immutable results,
decimal JSON round trips, and rejection of nonfinite values. Existing research
tests continue to cover the independent market-data interface.

## Consequences and follow-up

A real broker adapter can implement this interface without changing consumers.
Before accepting real account data, extend the model with broker/source identity,
snapshot timestamps and freshness, pagination/completeness, and stable instrument
identifiers. Test vendor error translation and account scoping using recorded,
sanitized fixtures. Provider selection, credentials, portfolio persistence, and
execution remain separate work; this decision does not complete those milestones.
