# Webull staged request journal

`security/webull_request_journal.py` adds durable registration of parsed runtime requests. Initialization exclusively creates a new SQLite file with a controller-selected account binding and pinned state digest. Existing files are never replaced, missing journals are not silently created during registration, and the request cannot set or advance the pinned context.

Registration uses an immediate transaction to check retained evidence, compare the expected state digest and consume the request ID. Concurrent copies produce only one registration. A valid but stale request is retained as blocked and its ID remains consumed; retry requires a new request. Invalid request syntax is rejected before registration. Request/receipt digests and identity/action agreement detect the tested accidental corruption before further writes. Verification reads a consistent transaction snapshot.

The registration receipt distinguishes duplicate-request checks and an expected digest match from authoritative state qualification. Caller authentication, owner approval, source qualification, controller admission, reset and execution remain false. The journal does not consume passkey approvals, clear latches, verify next-day/reset prerequisites or call a broker. Local registration time is persistence time, not an approval timestamp or broker watermark.

This is staged code validated in disposable test directories, not a deployed protected journal. Windows file ownership/ACLs, authenticated transport and controller-only write access must be enforced before production use. SQLite digests stored beside the data are not an independent integrity anchor: a writer could change both or delete history. Restoring an old copy could roll back consumed IDs. No deletion/rollback detection or recovery authorization is claimed; a recovered journal requires a protected recovery design. No real account risk state was initialized or adopted.

Six tests cover restart replay rejection, stale-state retention, concurrent duplicates, wrong account/corrupt receipt rejection, exclusive creation/missing-file refusal and invalid input without registration. See [qualification evidence](examples/webull-sandbox/request-journal-qualification.json). Durable request registration is not durable owner-approval replay protection and does not promote a launch gate.
