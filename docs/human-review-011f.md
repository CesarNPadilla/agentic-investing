# Phase v1.1f — synthetic baselines and flow-adjusted sleeve loss accounting

**FOUNDATION COMPLETE / FULL v1.1 INCOMPLETE.** The independent accounting workstream now derives sleeve risk inputs from explicit synthetic equity/flow evidence and persists it within the isolated PostgreSQL scope. See [current implementation status](examples/risk-policy-v11f/implementation-status.json).

The initial baseline records an explicit ID, timestamp and positive funded equity bounded by the approved $1,000 cap. A daily baseline records supplied marked equity and an aware timestamp identifying the same America/New_York date as the current snapshot. External flow IDs, signed amounts and posted times must be unique, ordered and within the interval after initial baseline through snapshot. Positive flows are deposits, negative flows withdrawals; internal transfers are excluded by the fixture contract. The initial funding event is represented by the baseline, not counted again as a post-baseline flow.

Current flow-adjusted equity equals current marked equity minus cumulative external flows. Daily start flow-adjusted equity equals daily marked baseline minus flows through that daily boundary. Daily P&L is the difference between these adjusted equities; cumulative P&L is adjusted current equity minus initial funded equity. Equity must include fees and both realized/unrealized effects, with explicit complete-ledger/reconciled-mark/fee-inclusion fixture assertions. Deposits/withdrawals do not create performance or reset cumulative loss. Approved daily/cumulative lesser-of bounds are retained, with equality triggering a required persistent latch. Nonpositive adjusted equity blocks new entries; missing or stale evidence blocks accounting.

Accounting persistence rejects initial baseline revision, earlier daily baselines, snapshot time regression, changed same-day baseline values, removed/changed previously recorded flows, retroactive new flows and changed same-cutoff evidence. New day evidence may change the daily denominator but never clears the persisted latch. The initial cumulative baseline remains fixed. No reset or baseline-replacement API exists; those operations require specified human ownership, qualified reconciliation and an authenticated design.

Accounting record and latch changes commit atomically. Subsequent assessments use persisted derived initial/current/start-of-day equity and daily/cumulative P&L rather than caller-provided substitutes. Attached accounting must remain fresh and match the risk snapshot cutoff; unavailable/incomplete evidence blocks new reservations. Before attachment, the original low-level synthetic diagnostic path remains available. This is not production trusted-data integration.
