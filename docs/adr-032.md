# ADR-032: isolate durable synthetic latch evidence before runtime integration

Status: v1.1b synthetic foundation implemented.

Persist v1.1 sleeve diagnostics in a dedicated explicitly initialized SQLite journal. Serialize verify/evaluate/append transactions, enforce monotonic latching, replay persisted results, fail closed on unavailable/inconsistent state and expose no reset API. Initialization and unlatched bootstrap are synthetic-only; no production database, runtime service or broker is integrated.

Use hash links as consistency checks without claiming immutable or externally authenticated audit. Full rewrites and valid suffix truncation require a future external trust anchor. PostgreSQL reservations, daily/cumulative baseline lifecycle and authenticated operational reset remain separate workstreams. See [owner review](human-review-011b.md).
