# ADR-037: qualify synthetic PostgreSQL process recovery in explicitly disposable infrastructure

Status: v1.1g isolated crash/outage recovery qualification complete.

Verify actual database-process stop/start recovery for committed baselines/latches/reservations, rollback of uncommitted state, and idempotent retry after a discarded receipt. Unknown status retains capacity, outage blocks new assessment and malformed numeric state produces a blocking typed error.

Require explicit disposable-container identity/label and localhost synthetic database before disruptive test operations; never target existing application services. Use a stable explicit localhost port across restart. Process recovery is not disk-loss/backup/high-availability qualification and does not grant execution permission. See [owner review](human-review-011g.md).
