# Webull bounded event supervision

The new `scripts/probe_webull_events.py` command observes the selected retail cash sandbox event stream in a hidden diagnostic child. The parent creates a Windows kill-on-close job, attaches the child, then publishes a unique startup handshake. Credential access and network initialization wait for that handshake. The sandbox host and TLS are fixed, account selection is freshly checked, retries are disabled, and SDK stdout/stderr are discarded because the installed SDK prints signed request metadata. Payloads and account identifiers are not copied into diagnostic output.

The parent imposes a 1–45 second observation deadline, closes the containment job and waits for child exit. Private reports use atomic replacement during callbacks; each invocation has a separate observation file. This is a bounded diagnostic under the engineering identity, not a deployed service under AgenticPaperRuntime. It does not qualify broker permissions, reconnection, missed-event coverage, halt status or accounting.

An actual 35-second invocation received subscription acknowledgement and one heartbeat, with no error or unclassified message observed. The deadline closed the job and the child exited. No order was placed to generate an event. The last callback occurred approximately 20 seconds after stream initialization; that is local observation timing, not an authoritative broker watermark. [Qualification evidence](examples/webull-sandbox/event-supervision-qualification.json) preserves this scope.

The reviewed [retail subscription documentation](https://developer.webull.com/apis/docs/reference/custom/subscribe-trade-events/) describes success, heartbeat and error types, and says subscription type 1 is supported. The installed SDK's request builder sends type 7. The successful acknowledgement is evidence of an accepted connection, not proof that all required order messages are covered. This discrepancy remains unqualified; no undocumented request override was introduced. The reviewed page does not establish the required disconnect replay contract.

Tests exercise deadline cleanup, failed containment before startup handshake, disabled-execution enforcement, private input paths and duration limits. The remaining actual-runtime boundary check requires the owner-held Windows runtime password; it cannot be substituted by this engineering-session diagnostic.
