# Phase v1.1d — integrated PostgreSQL synthetic transaction qualification

**FOUNDATION COMPLETE / FULL v1.1 INCOMPLETE.** Docker became available during this phase. Qualification used a new disposable PostgreSQL 17.11 container bound to localhost, with generated temporary credentials held only in process memory/environment. It was removed after testing. Existing application/database containers, credentials, policy configuration and persistent application data were not changed. See [current status](examples/risk-policy-v11d/implementation-status.json).

The isolated PostgreSQL scope combines approved sleeve mathematics, sticky loss/manual latch, capacity reservation and diagnostic event in one SERIALIZABLE transaction under an aggregate row lock. Missing scope does not bootstrap implicitly. Default initialization is latched; unlatched initialization is explicit synthetic test evidence. Serialization/deadlock failures retry against newly loaded state up to five times, then block. Receipts return only after commit; an update/commit failure cannot return a successful reservation.

Ledger-managed pending and retained filled costs are added to same-symbol and gross commitments and deducted from available cash before risk checks. External fixture baseline commitments must exclude these ledger amounts. Conservative acquisition amounts include fees and serve as a bounded synthetic proxy for marked exposure; this is not qualified live valuation. Different symbols can consume separate position capacity while aggregate limits remain enforced. Exact proposal identity/symbol/input digest retries avoid duplicate reservation; changed or terminal identity reuse rejects. A retry under a persisted latch remains blocked by risk while its previously established reservation stays recorded.

Partial fills, unknown/pending-cancel status and unverified terminal evidence retain capacity. Verified synthetic terminal evidence releases only the unfilled amount; actual filled acquisition costs remain consumed. Loss diagnostics atomically persist the latch without creating a reservation. A concurrent reservation may commit before a loss transaction; every subsequent assessment is blocked after the loss commits. No automatic cancellation or liquidation is implied. There is no reset API.

Validation: **14 PostgreSQL tests**, plus previous targeted suites, **204 passed with no skips** on PostgreSQL 17.11. Coverage includes concurrent capacity contention and duplicates, same-symbol/gross risk integration, daily/cumulative latch persistence, concurrent loss/reservation ordering, partial-fill restart/terminal lifecycle, changed digests, failed-update rollback, missing/corrupt state, default latch, real SQLSTATE serialization-error retry and retry exhaustion. Retry fixtures inject serialization exceptions inside real transactions; concurrent writer tests exercise actual PostgreSQL contention. Static checks, output schema, source digests and git diff --check pass.

This qualifies bounded synthetic transactional behavior only. The JSON aggregate stores events but does not provide externally anchored or tamper-proof audit; structural/budget checks cannot prevent a privileged database owner rewriting consistent state. Initialization is independent of earlier SQLite stores; no operational latch/balance migration is implemented. Production load, database-process crash recovery, account/symbol inventory migrations, dynamic cash/valuation changes, trusted broker evidence and authenticated operations remain unqualified. The helper test suite skips without an explicit isolated test DSN; this qualification run supplied one and skipped nothing.

Next integration work must address authoritative marked/account evidence, baseline/day/reset lifecycle and operational ownership; complete whole-account loss and exposure choices before affected branches. Production security, migrations, recovery and immutable audit qualification remain required. Existing runtime risk evaluator/API/broker are not wired to this foundation. The full v1.1 gate is incomplete, and this phase grants no paper/live permission.

Research cap remains **$1,000**; production funding planned/unconfirmed; execution flags disabled. Strategies/historical/OOS evidence unchanged; 2026 OOS sealed; forward paper **0/60**. No broker operation or application service restart occurred.
