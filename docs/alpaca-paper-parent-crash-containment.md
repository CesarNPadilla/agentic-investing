# Parent-crash containment for the event monitor

The process-supervised event observer now runs in a non-inheritable, unnamed Windows job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` and no breakaway flags. [Microsoft documents](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) that closing the last handle terminates the associated processes. An actual subprocess test terminates the parent, then waits on the child's process handle to verify the child's termination; it does not infer termination from a missing heartbeat or PID lookup alone.

The fixed child command additionally receives a private, unique startup gate and matching token. Before reading credentials, touching the ledger or connecting to a provider, the child waits at most five seconds for the gate. The parent releases it only after job assignment succeeds. Assignment failure leaves the gate closed, terminates the child and persists the watchdog failure. If the parent dies before assignment/release, the unassigned child exits on its bounded gate timeout without source access. A successful job assignment protects the released child from becoming orphaned on parent death. Gate files are never reused; normal exit removes the gate created by that invocation.

An actual dedicated-account supervised run completed three checks with matching cash/positions and execution disabled. All 299 selected paper-control tests passed, including parent-death termination, missing/mismatched startup gates and assignment-failure rejection. The durable parent session is claimed before launch; a crashed parent still leaves an incomplete session requiring recovery. Containment terminates the child; it does not authorize reconnecting or repairing that session automatically.

This applies to the fixed event-process supervisor entry point. Persistent Windows service installation, reconnect/gap recovery, crash-recovery acknowledgement, status bootstrap, publication/cutoff accounting and independently protected risk-reset authority remain unqualified. Parent persistence/process creation still have latency; no global hard real-time claim is made. All risk latches and execution flags remain unchanged, INTC stays disabled and the month trial has not started.
